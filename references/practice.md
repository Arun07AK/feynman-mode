# Past papers: priority and practice

## Priority

- Analyse every in-scope paper. Papers of the exam the learner is sitting count most; use them to set the question pattern and weightage.
- Give each topic stars with a one-line reason, from frequency, marks and scoring potential. Say where the evidence is thin.
- Stars set study order, practice volume and revision priority. They never decide whether a topic is taught properly.

## Scope of each question

Classify every question part IN, PARTIAL or OUT against the syllabus, with the evidence in `SCOPE.md`. Drop what is out. Use only the in-scope part of a partial question.

## Practice

- Practice uses only real past-paper questions, shown as crops of the original or copied word for word, with the same wording, order and punctuation. The learner practises in the exam's own language. Only the solutions are original.
- Never write your own questions, and never present anything as a past question that is not one.
- If the learner has no past papers, say so and ask. Practice then comes from exercises they supply, and from the fresh-problem checks inside each thread. Do not fill the gap with invented papers.
- Map questions by topic and by module. A layout that has worked well:
  - a numbered grid of questions;
  - one question at a time: a working area for the attempt, then the worked solution (the picture or reasoning first, numbered steps, one "Remember it" line), then a self-grade of Got, Partial or Missed, saved.
- Shape the attempt area to the subject analysis: paper working for calculation, a blank page for derivations, a model answer to compare with for design and essays.
- Recompute every number in a worked solution with code before publishing it.
- Build a mock for each real in-scope paper, in printed order, and one short revision layer for the last days.
- For a longer explanation of a solution or a doubt, send the learner to that topic's thread. Do not build static explanation pages.
